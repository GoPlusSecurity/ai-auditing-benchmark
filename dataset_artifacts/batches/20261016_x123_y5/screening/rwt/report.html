RWT Exploit Analysis

Date: 2026-07-19

Loss Estimate: 158,616.474391739315146216 USDT (~$158,616.47) drained from the RWT/USDT Pancake pair; direct attacker proceeds were 118,069.281571404198479027 USDT before gas.

I. Executive Summary

  • Verdict: Confirmed Exploit - privileged AMM reserve burn / price manipulation.
  • Root Cause: The verified RWT token at 0xf8A36777415C09fEAfF3dC78DcBb3ed00ce989Cd exposes burn(address _From, uint256 _amount) to any address in its custom role mapping. At the focal block, the unverified trading contract 0x8812bB5fB89D69D35Ac84D2C37B55769395b9f90 had that role and its public sell path repeatedly burned RWT directly from the Pancake pair 0xC1c2ef25372f12CE18d35044446064B720C4aA27, then called sync(). This destroyed the pair's RWT reserve while leaving enough USDT reserve for successive overpriced RWT-to-USDT swaps.

II. Vulnerability

A. Business Logic Context

RWT is an ERC-20 paired against USDT on PancakeSwap. The token uses a custom Ownable implementation where onlyOwner actually checks a role mapping, not just the _owner address. The token also keeps the Pancake pair address in pancakeSwapPair and applies transfer restrictions only when both from and to are nonzero.

The focal block read-only calls confirmed hasRole(0x8812...f90) == true, owner() == 0x418a87640bEebAca8f013D237EE5595a521a6D3b, and pancakeSwapPair() == 0xC1c2ef25372f12CE18d35044446064B720C4aA27.

B. The Vulnerability

// RWT/RWT.sol at 0xf8A36777415C09fEAfF3dC78DcBb3ed00ce989Cd
modifier onlyOwner() {
    require(hasRole(_msgSender()), "Ownable: caller is not the owner");
    _;
}

function setRole(address addr, bool t) public onlyOwner {
    role[addr] = t;
}

function burn(address _From, uint256 _amount) external onlyOwner {
    _burn(_From,_amount);
}

// RWT/RWT.sol at 0xf8A36777415C09fEAfF3dC78DcBb3ed00ce989Cd
function _update(address from, address to, uint256 value) internal virtual override {
    if (from != address(0) && to != address(0)) {
        // pair buy/sell and transfer restrictions are only applied here
    }

    super._update(from, to, value);
}

The broken invariant is that a role holder can burn tokens from any account, including the AMM pair. Burning from the pair also bypasses the transfer checks because the burn goes to address(0), so the branch guarded by from != address(0) && to != address(0) does not run.

C. Why It Was Exploitable

The precondition was a role-bearing external contract that exposed the privileged burn behavior through a public sell workflow. get_source_code_list returned no verified source for 0x8812...f90, and heimdall was not available in this environment, so the sell internals are treated behaviorally. The trace nevertheless shows every relevant effect: calls from 0x7ed953...f4CE into 0x8812...f90.sell(...), then 0x8812...f90 swapping through Pancake Router, transferring USDT back to the attack contract, calling RWT.burn(pair, amount), and calling pair.sync().

III. Technical Attack Flow

  1. The attacker EOA 0x84DD3A5D4DE44c8ad0CE032BeAb8bc3f01D1dcf7 deployed the unverified attack contract 0x7ed953Ff42509568f620aa340a33A9373447f4CE in 0xe552cb8b968ae45126c56508e9d1c8a3c8a136a1e1fa95befcef7c0b1da2b28c. The trace is a CREATE from the EOA to 0x7ed953...f4CE.
  2. In the focal transaction 0x22300140e7c44899c2602382a6e7a4a34a70f47f9736721744bc6434c07171dc, the attack contract borrowed 1,000,000 USDT from 0x8F73b65B4caAf64FBA2aF91cC5D4a2A1318E5D8C.
  3. The attack contract called 0x8812...f90.buy(...), paying 93,612.061013797236332471 USDT. The contract sent a 15% fee of 14,041.809152069585449870 USDT to 0x17Eb8c8510A2A88b690eFa9fBE671Db7dE44e6FE, swapped 79,570.251861727650882601 USDT into 36,718,733.010848105074881558 RWT, and transferred that RWT to the attack contract.
  4. The attack contract then repeatedly entered 0x8812...f90.sell(...) with decreasing RWT amounts. A representative early cycle sold 35,984,358.350631142973383908 RWT for 235,902.720974496353639994 USDT, transferred 200,517.312828321900593997 USDT to the attack contract, deposited 11,795.136048724817681999 USDT to the reward contract, then burned 71,968,716.701262285946767816 RWT from the pair and synced reserves.
  5. The same loop continued until the pair's RWT reserve was reduced from 110,156,199.032544315224643753 RWT to 0.000000000000000003 RWT. Near the end, the trace shows RWT.burn(pair, 308), pair.sync(), reserves of 126.178072407348364571 USDT and 3 wei RWT, flash-loan repayment of 1,000,000 USDT, and final transfer of 118,069.281571404198479027 USDT from the attack contract to the EOA.
