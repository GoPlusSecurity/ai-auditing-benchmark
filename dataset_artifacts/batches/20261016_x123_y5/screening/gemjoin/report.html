Balance Coin BTCB Oracle Exploit Analysis

Date: 2026-07-21

Loss Estimate: 761,696.595696317977899753 USDT realized in the focal tx; 4,500,996.403005769162181029 BLC was newly minted and the final BTCB urn carried 4,925,000 BLC debt against 0.006284011757633665 BTCB.

I. Executive Summary

  • Verdict: Confirmed Exploit / Oracle-Driven Overborrowing
  • Root Cause: The BTCB oracle path accepted and propagated an absurd BTCB/USD median value of 1e33. In the prior tx, median 0xdc691...df7b accepted that value from an authorized signer with bar=1; the focal tx rolled OSM 0x2F950...6239, then Spotter.poke(BTCB) at 0x849...9228 wrote Vat.ilks[BTCB].spot = 666666666666666666666666666666666666666666. The verified Vat.frob safety check depends on tab <= urn.ink * ilk.spot, so the inflated spot let the attacker leave only 0.006284011757633665 BTCB locked while raising debt to 4,925,000 BLC and withdrawing/selling the rest.

II. Vulnerability

A. Business Logic Context

Balance Coin uses Maker-style accounting. Vat stores collateral (ink) and normalized debt (art) per ilk/urn, GemJoin moves external collateral into and out of Vat.gem, and BlcJoin mints external BLC after moving internal Vat.blc credit.

For BTCB, Spotter.ilks(BTCB) returned pip 0x2F950...6239 and liquidation ratio mat = 1.5e27. The focal trace shows Spotter.poke(BTCB) reading pip.peek() -> (1e33, true) and calling Vat.file(BTCB, "spot", 666666666666666666666666666666666666666666).

The oracle contracts (0xdc691...df7b, 0x2F950...6239, 0x849...9228) and the delegated attacker implementation (0x7c20...e200) had no verified source from the MCP source API, and no decompiler binary was available. Their behavior is therefore established from execution traces, public getters, and state deltas rather than source.

C. Why It Was Exploitable

The median had bar() = 1, and the signer recovered in the setup tx, 0x79FFB5572ae52b51DB996Ae5cfc09c48C569C67b, returned orcl(signer) = 1. One authorized signature was therefore enough to accept the 1e33 BTCB value. The on-chain evidence does not prove whether that signer was compromised or intentionally used; it proves the submitted payload was accepted as authorized.

The OSM wrapper showed hop() = 3600, src() = 0xdc691...df7b, and bud(0x849...9228) = 1, so the spotter could read the delayed price after the hour boundary. Before the focal tx, Vat.urns(BTCB, attacker) was ink=10.743371477925676076 BTCB, art=424,003.596994230837818971 BLC, and Vat.ilks(BTCB).spot was about 3.959793333333333e31. After the focal oracle update, spot became 6.666666666666666e41, making the vault appear massively overcollateralized despite almost all BTCB being withdrawn.

III. Technical Attack Flow

  1. In preparation tx 0xe54b...cbaf, the attacker submitted median value 1000000000000000000000000000000000 and the trace recovered authorized signer 0x79FF...C67b. The same tx called OSM.poke; raw OSM state set the next value to 1e33 while current remained 60,200.38.

  2. The same setup tx flash-loaned 719,576 USDT, swapped it through PancakeSwap V3 for 10.743371477925676076 BTCB, transferred that BTCB into GemJoin 0xe536...85ba, and called Vat.frob(BTCB, ..., dink=10.743371477925676076, dart=424003.596994230837818971).

  3. In focal tx 0xe7ab...7628, the attacker called OSM.poke(). OSM storage advanced zzz from 1784664000 to 1784667600 and promoted the packed value containing 1e33.

  4. Spotter.poke(BTCB) then called 0x2F950...6239.peek() -> (1e33, true) and Vat.file(BTCB, "spot", 666666666666666666666666666666666666666666), inflating the BTCB collateral value used by Vat.frob.

  5. The attacker called Vat.frob(BTCB, ..., dink=-10.737087466168042411, dart=0) and GemJoin.exit, causing 0xe536...85ba to transfer 10.737087466168042411 BTCB to the attacker.

  6. The attacker then called Vat.frob(BTCB, ..., dink=0, dart=4500996.403005769162181029) and BlcJoin.exit, minting 4,500,996.403005769162181029 BLC.

  7. The attacker swapped the BLC through PancakeSwap V2 router 0x10ED...024E, sending 4,500,996.403005769162181029 BLC to pool 0x1394...3CA and receiving 52,833.89079310959160347 USDT.

  8. The attacker swapped the withdrawn BTCB through PancakeSwap V3 router 0x13f4...8Dd4; pool 0x46Cf...a7C4 received 10.737087466168042411 BTCB and sent 708,862.704903208386296283 USDT.
