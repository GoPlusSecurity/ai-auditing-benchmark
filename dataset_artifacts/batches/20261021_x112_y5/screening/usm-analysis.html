USM/FUM Exploit Analysis

Date: 2026-08-09

Loss Estimate: 70.830977367697708372 ETH (~$136,124 at the on-chain USM oracle price of $1,921.813593/ETH)

I. Executive Summary

  • Verdict: Confirmed Exploit / FUM Pricing Round-Trip Attack
  • Root Cause: The verified USM contract at 0x2a7fff44c19f39468064ab5e5c304de01d591675 prices fund() and defund() with approximate, non-invariant-preserving average-price math. A large flash-loaned fund() raised the internal ETH/USD price and minted 62,184,299.031602985197125048 FUM; the attacker then split the newly minted FUM into 64 defund() burns, each priced from the inflated internal state, so aggregate ETH redeemed exceeded the ETH deposited by 70.830977367697708372 ETH.

II. Vulnerability

A. Business Logic Context

USM is the Minimalist USD contract and FUM is its funding token. fund() accepts ETH and mints FUM against the pool buffer, while defund() burns FUM and sends ETH back from the same pool. The intended invariant is that a same-transaction FUM round trip should be loss-making or neutral after sliding-price impact, not profitable.

The pool also keeps an internal ethUsdPrice and bidAskAdjustment that move with user activity. In this transaction the oracle returned about $1,921.813593/ETH, while pool state after the exploit stored an internal price around $6,579,253.311578/ETH and bid/ask adjustment around 3,423.460707.

B. The Vulnerability

// contracts/USM.sol @ 0x2a7fff44c19f39468064ab5e5c304de01d591675
function _fundFum(address to, uint minFumOut) internal returns (uint fumOut) {
    LoadedState memory ls = loadState();
    ls.ethPool -= msg.value;
    ...
    (fumOut, adjGrowthFactor) = fumFromFund(ls, fumSupply, msg.value, debtRatio_, isDuringPrefund());
    require(fumOut >= minFumOut, "Limit not reached");
    ls.bidAskAdjustment = ls.bidAskAdjustment.wadMulUp(adjGrowthFactor);
    ls.ethUsdPrice = ls.ethUsdPrice.wadMulUp(adjGrowthFactor);
    _storeState(ls);
    fum.mint(to, fumOut);
}

function _defundFum(address from, address payable to, uint fumToBurn, uint minEthOut) internal returns (uint ethOut) {
    LoadedState memory ls = loadState();
    ...
    (ethOut, adjShrinkFactor) = ethFromDefund(ls, fumSupply, fumToBurn);
    require(ethOut >= minEthOut, "Limit not reached");
    ls.bidAskAdjustment = ls.bidAskAdjustment.wadMulDown(adjShrinkFactor);
    ls.ethUsdPrice = ls.ethUsdPrice.wadMulDown(adjShrinkFactor);
    require(debtRatio(ls.ethUsdPrice, ls.ethPool - ethOut, ls.usmTotalSupply) <= MAX_DEBT_RATIO, "Debt ratio > max");
    fum.burn(from, fumToBurn);
    _storeState(ls);
    to.sendValue(ethOut);
}

The pricing helpers are the vulnerable primitive: fumFromFund() prices one large buy using a geometric average, while ethFromDefund() prices each sell using a separately recomputed arithmetic average. Those two approximations are not exact inverses, and there is no cumulative same-transaction invariant checking that newly minted FUM cannot be redeemed for more ETH than was just deposited.

// contracts/USM.sol @ 0x2a7fff44c19f39468064ab5e5c304de01d591675
function fumFromFund(...) public pure returns (uint fumOut, uint adjGrowthFactor) {
    ...
    uint avgFumBuyPrice = fumBuyPrice0.wadMulUp(fumBuyPrice1).wadSqrtUp();
    fumOut = ethIn.wadDivDown(avgFumBuyPrice);
}

function ethFromDefund(...) public pure returns (uint ethOut, uint adjShrinkFactor) {
    ...
    uint avgFumSellPrice = fumSellPrice0 + fumSellPrice2;
    unchecked { avgFumSellPrice /= 2; }
    ethOut = fumIn.wadMulDown(avgFumSellPrice);
}

C. Why It Was Exploitable

The pool was small enough that a flash loan could dominate its state: ethPool() was 132.588942983107019337 ETH before the focal call, and the attacker funded it with 11,579.978354608392803524 ETH. Because defund() was open after prefund and only enforced minimum output plus the max-debt-ratio check, the attacker could immediately burn the minted FUM in chunks. The oracle did not reset the manipulated internal price during the loop because the fresh oracle value remained the same after the first update.

III. Technical Attack Flow

  1. 0xb92b2e47680c89da8f951b8963ef469f461a50fc called the unverified attack contract 0x5a5e29ba89663a3558273354e990426f3cac7de7 in the focal transaction.
  2. The attack contract borrowed 11,579.978354608392803524 WETH from Morpho (0xbbbbbbbbbb9cc5e90e3b3af64bdaf62c37eeffcb), unwrapped it, and called USM.fund{value: 11579.978354608392803524 ETH}.
  3. fund() minted 62,184,299.031602985197125048 FUM to the attack contract. The trace shows PriceChanged moving the internal price to about $7,164,588.330708/ETH after this funding step.
  4. The attack contract then executed 64 defund() calls, burning roughly 971,629.672368796643705079 FUM per call. The first chunk returned 182.043926127399815483 ETH; the final chunk returned 182.041991342444874875 ETH.
  5. The contract wrapped exactly 11,579.978354608392803524 ETH back into WETH, approved Morpho, and repaid the flash loan.
  6. The remaining 70.830977367697708372 ETH was sent to 0xe3c6346b6f282029312d2caf4677ef39beabbf99.
