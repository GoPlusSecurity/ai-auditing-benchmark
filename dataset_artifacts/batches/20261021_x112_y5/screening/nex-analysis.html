Date: 2026-08-03

Loss Estimate: 40,279,208.819696511790081586 AIC drained from the NEX/AIC pair; attacker realized 32.361267289208020008 BNB gross ($21,503.92) and 32.359524394208020008 BNB net after gas ($21,502.76).

I. Executive Summary

  • Verdict: Confirmed Exploit - NEX transfer double-count / AMM reserve manipulation.
  • Root Cause: The NEX token at 0xaE04AE29bdB7aB7Eb249d3aFa7Bc3D37564e8Cf9 overrides _transfer so router-involved transfers call super._transfer(from, to, amount) once in the isRouter branch and then fall through to a second unconditional super._transfer. The attacker forced the Pancake NEX/AIC pair to skim NEX to the router, causing a double debit from the pair, then called sync so the pair recorded a near-zero NEX reserve. A follow-up swap against that corrupted reserve withdrew nearly all AIC from the pair and converted the proceeds to BNB.

II. Vulnerability

A. Business Logic Context

NEX is a fee-on-transfer token paired against AIC on a PancakeSwap V2-style pair. Its intended behavior is to take DAO/node fees on sells into automated market-maker pairs while allowing router interactions.

The Pancake pair is standard: skim(to) transfers token balances above stored reserves to any recipient, and sync() updates reserves to current token balances. Those functions assume token transfers move exactly the requested amount from the pair once.

B. The Vulnerability

// contracts/flatten/nexus_nex.sol @ 0xaE04AE29bdB7aB7Eb249d3aFa7Bc3D37564e8Cf9
function _transfer(address from, address to, uint256 amount) internal override {
    ...
    bool isSell = automatedMarketMakerPairs[to];
    bool isRouter = (from == uniswapV2Router || to == uniswapV2Router);

    if (isRouter){
        super._transfer(from, to, amount);
    } else if (isSell){
        uint256 daoTokens = amount.mul(daoFee).div(100);
        uint256 nodeTokens = amount.mul(nodeFee).div(100);
        amount = amount.sub(daoTokens).sub(nodeTokens);
        ...
    }

    super._transfer(from, to, amount);
}

The missing return or else after the isRouter branch violates the ERC-20 invariant that one transfer call moves amount once. When from is the NEX/AIC pair and to is the Pancake router, a single transfer(router, amount) debits the pair twice and credits the router twice.

// Contract.sol PancakePair @ 0x974C0078740480aE830D379fDB8d5f441C9dDC75
function skim(address to) external lock {
    address _token0 = token0;
    address _token1 = token1;
    _safeTransfer(_token0, to, IERC20(_token0).balanceOf(address(this)).sub(reserve0));
    _safeTransfer(_token1, to, IERC20(_token1).balanceOf(address(this)).sub(reserve1));
}

function sync() external lock {
    _update(IERC20(token0).balanceOf(address(this)), IERC20(token1).balanceOf(address(this)), reserve0, reserve1);
}

C. Why It Was Exploitable

The pair already held a large NEX reserve. The helper contract created a NEX surplus just above the pair's reserve, then chose the Pancake router as the skim recipient specifically to trigger NEX's router branch. Because the requested skim amount was about half the pair's NEX balance, the double debit did not revert and left the pair with only 1 wei of NEX. sync() then made that manipulated balance the official reserve, breaking the constant-product pricing basis for the next swap.

III. Technical Attack Flow

  1. Focal tx created 0xF0F74b90aFB29903C80ED7531B50764C49089E25, which created unverified helper 0x29977d9B8a888B17BFfA2958b003956a5E8BE69A and invoked selector 0x28022411.
  2. The helper called sync() on the AIC/USDC pair 0xe89636FB73D04Db51e5Fbd0Ce1379fb8d2b96415, then flash-swapped out 42,982,239.623681550888856012 AIC.
  3. Inside pancakeCall, the helper routed the borrowed AIC through the NEX/AIC pair 0x974C0078740480aE830D379fDB8d5f441C9dDC75, receiving 33,784,701.156466997300742224 NEX.
  4. The helper sent 33,765,346.758312339612076744 NEX back to the NEX/AIC pair. NEX's sell fee sent 2,025,920.805498740376724604 NEX to fee address 0x0f7e35653f6A8E09A0865a183B51177e16237CB5 and 31,739,425.952813599235352140 NEX to the pair, creating a skimmable excess.
  5. The helper called skim(0x10ED43C718714eb63d5aA57B78B54704E256024E). The trace records two identical NEX Transfer logs from the pair to the router for 31,739,425.952813599235352140 NEX; afterward sync() set NEX/AIC reserves to 1 wei NEX and 83,261,448.443378062678942187 AIC.
  6. The helper swapped its remaining 19,354.398154657688665480 NEX into the now-corrupted pair. After the NEX fee, the pair saw only 18,193.134265378227345552 NEX input, but because the stored NEX reserve was 1 wei, Pancake's swap math released 83,261,448.443378062678937598 AIC, leaving only 4,589 wei AIC in the pair.
  7. The helper repaid the flash swap with 43,093,993.446703122921167038 AIC, which included a 111,753.823021572032311026 AIC flash-swap fee, and sold the remaining 40,167,454.996674939757770560 AIC through AIC/USDC and USDC/WBNB for 21,503.921643594504179252 USDC and then 32.361267289208020008 WBNB, which was unwrapped and sent to the attacker EOA.
