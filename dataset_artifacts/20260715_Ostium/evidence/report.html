Ostium Future-Dated Price Report Exploit Analysis

Date: 2026-07-15

Loss Estimate: 1,078,403.5804 USDC from the Ostium oLP vault (~$1,078,403.58); attacker net +1,078,319.4804 USDC after 84.1 USDC retained by protocol storage/fees.

I. Executive Summary

  • Verdict: Confirmed Exploit / Future-Dated Oracle Report Abuse
  • Root Cause: OstiumPrivatePriceUpKeep.performUpKeep(bytes) on proxy 0xb71ec9ebd8145dacacf6724363143cb5667a3d36 (implementation 0x0aebc4094b60ea4e21e937e80dafdd58c07c5ebb) accepted signed reports whose timestamp was in 2033 because it only rejected reports older than the order timestamp. OstiumVerifier.verify(bytes) at 0xd456939e54f68ef9b0be62abb2ec4a37397cb814 only checked that the report was signed by an authorized signer and returned the report data. The attacker batched an open at price 5,000 and a close at price 60,000 for the same trade in one transaction.

II. Vulnerability

A. Business Logic Context

Ostium market orders are created first, then an upkeep contract verifies a signed price report and calls the trading callbacks to settle the order. A valid close report must represent a real price after the order was created; otherwise a trader can choose prices rather than accept market prices.

B. The Vulnerability

// src/OstiumPrivatePriceUpKeep.sol
// proxy 0xb71ec9ebd8145dacacf6724363143cb5667a3d36 -> implementation 0x0aebc4094b60ea4e21e937e80dafdd58c07c5ebb
(reportFeedId, timestamp, a.price, a.bid, a.ask, isMarketOpen, a.isDayTradingClosed) =
    abi.decode(verifierResponse, (bytes32, uint32, int192, int192, int192, bool, bool));

if (
    expectedFeedId != reportFeedId || block.timestamp > order.timestamp + maxOrderAgeSeconds
        || timestamp < order.timestamp
) {
    revert InvalidPrice(orderId);
}

fulfill(a);

// src/OstiumVerifier.sol at 0xd456939e54f68ef9b0be62abb2ec4a37397cb814
function verify(bytes calldata signedReport) external view returns (bytes memory verifierResponse) {
    (bytes memory reportData, bytes32 r, bytes32 s, uint8 v) =
        abi.decode(signedReport, (bytes, bytes32, bytes32, uint8));
    address signer = ecrecover(keccak256(abi.encodePacked('\x19Ethereum Signed Message:\n32', keccak256(reportData))), v, r, s);
    if (!isAuthorizedSigner[signer]) revert NotAuthorizedSigner(signer);
    return reportData;
}

The missing invariant is an upper bound on the report timestamp, such as timestamp <= block.timestamp or a tight relation between report timestamp and order timestamp. The focal reports both used timestamp 2000000000 (2033-05-18 03:33:20 UTC), while the block timestamp was 1784125432 (2026-07-15 14:23:52 UTC). The recovered signer was 0x38110430184c22d93c30b3e67b9af98d5d0ab8bd, and isAuthorizedSigner returned true.

C. Why It Was Exploitable

The attacker had a delegated execution route through 0xfe12f6360000de49d5506d52ee5ac4bc9dd5bd2e and could submit a batch that created an order and immediately fulfilled it. Because maxOrderAgeSeconds was 60 and the orders were created in the same transaction, the order-age check passed. Because the report timestamp was far in the future, the timestamp < order.timestamp check also passed.

III. Technical Attack Flow

  1. The relayer EOA 0xd1794196f0fc99c7f27970e661597d77d9a85869 called executeBatch(address[],bytes[]) on 0xfe12f6360000de49d5506d52ee5ac4bc9dd5bd2e in the focal transaction. The four targets were Ostium trading, price upkeep, trading, and price upkeep.
  2. The first delegated action for trader 0x321df194646029e7a6193ea05573d4b9c398bfd9 opened a market long on pair 0 with 120,000 USDC collateral, 1x leverage, and wanted price 5,000. The order id was 0x20ebcf.
  3. The first upkeep fulfilled order 0x20ebcf using feed 0x7404e3d104ea7841c3d9e6fd20adfe99b4ad586bc08d8f3bd3afef894cf184de, timestamp 2000000000, and price/bid/ask all 5,000.
  4. The second delegated action immediately called closeTradeMarket(pairIndex=0,index=0,closePercentage=10000,marketPrice=60000,slippageP=1000), creating close order 0x20ebd0 and charging a 0.1 USDC oracle fee.
  5. The second upkeep fulfilled order 0x20ebd0 with the same future timestamp 2000000000, but price/bid/ask all 60,000. The close callback then called sendAssets(uint256,address) on the oLP vault for 1,078,439.5804 USDC and returned 119,879.9 USDC plus a 0.1 USDC oracle refund from trading storage.
